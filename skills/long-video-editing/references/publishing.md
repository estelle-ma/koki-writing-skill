# 封面、正式标题、shownote 与时间轴

用于已经进入发布阶段的教程或访谈长视频，也可单独处理已有成片的发布素材。根据本次请求执行对应部分；延用已经确认的内容与视觉，不要求用户重新走一轮选题或审批。

## 先确认当前成片与已批准方向

- 读取用户指定的当前项目或最终视频，确认实际顺序、时长及现有章节。之前的完整文稿、剪辑稿和原片时间只是查找依据，不能直接当成成片时间轴。
- 复用已校对的姓名、产品名、案例名称、栏目名称、身份、链接和优惠信息。说话人或 ASR 标签有误时，按已确认文稿与真实内容纠正，不把转写错误带进标题和 shownote。
- 用户只要封面或文案时，不改视频时间线、字幕、素材和样式。用户要求先讨论标题时，先讨论；已有明确标题或已选定版本，就继续制作。
- 发布素材的语言沿用视频、平台及用户要求。中文写成自然中文，不机械翻译英文；用户要求英文时先核对语法、拼写和产品名。

## 封面标题与正式标题各司其职

封面用简短、醒目的核心钩子；正式标题补充本期承诺、内容形式或具体反差，不必逐字重复封面。

| 视频类型 | 封面侧重 | 正式标题侧重 |
| --- | --- | --- |
| 教程、软件实操、多案例 | 真实目标、使用体验或结果 | 工具名、教程性质、具体用途与实际案例数量 |
| 访谈、人物栏目 | 人物的具体故事、反差、关键问题 | 用户要求的栏目名，加具体场景和人物看点 |

访谈可以轻松、有梗，用具体情节形成好奇心；教程让人知道点进去能学会什么。案例数、融资额、身份和成绩必须有内容依据。没有说过的主持人经历不能为制造反差而编出来；嘉宾的个人说法不能包装成已独立核验的事实。

## 封面制作与续改

需要制作位图封面时，加载当前可用的 video-cover / 图像生成工作流。在 Codex 中优先使用内置 image_gen；本地参考先查看，再注明原照片、文字风格图和待改封面各自的作用。

### 真实画面与人物

- 用户指定“当前视频某时刻的截图”时，从最新成片定位该时刻，映射回对应源素材与源时间，再提取干净帧。不要误取原片的同名时间点；不从已经含字幕、花字、人物介绍或进度条的合成画面直接截成封面。
- 先保留一份干净原帧，再单独添加封面文字。用户要真实原片风格时，保持真实场景、人物、服装、表情和相对位置；不要以重新生成的人物、姿势、道具或场景替代截图。
- 保持身份、五官、眼镜、发型与自然肤色。人物应自然、精神、愉悦；避开疲惫表情和像在说“不要”的手势。仅在用户要求时做适量美颜与妆造，不换脸、不重塑身份。
- 双人访谈要让人感到在对谈，避免默认肩靠肩、亲密合影的构图。用户已经选定真实双人截图时，尊重这张真实画面，不为了表现对谈而添加不存在的麦克风或重摆人物。
- 原图与生成结果分别检查。经过生成式重绘的区域，不声称像素完全未变；用户要求保留原照片时，验收人物与背景是否确实保留。

### 文字、字体与版式

- **沿用已批准的字体与视觉。** 换截图、调整字号、改换行或扩展比例，不等于可以换字体、颜色和字重。把批准的封面作为文字风格参考传入；不能一边说“沿用”，一边悄悄替换成另一种普通字体。
- 制作醒目大字封面时，优先把主标题排成两行；栏目名另作小一层标识。用户要求至少占画面三分之一时，按这个占比安排标题区域，缩成手机缩略图复查，而不是把主标题压成一条细长横字。
- 字少、字大、层级明确，少量关键词强调。背景复杂时用局部渐变、半透明浅底或小框提高对比；避免花哨描边、贴纸和额外口号，不遮眼睛、鼻子、嘴巴。
- 人物、留白和文字互相让位。需要更大的标题时先调整构图，不能通过遮脸或把人拉宽来凑空间。
- 可选示例：厚重的中文粗体、深蓝主字、橙色关键词、局部米白半透明底和两行大标题。只有与本期已确认风格一致时才使用，不把示例当成用户已认可的样式。

### 四种规格与交付

默认独立构图输出四张 PNG；用户指定其他尺寸时以用户要求为准：

| 比例 | 目标像素 |
| --- | --- |
| 16:9 | 1920×1080 |
| 9:16 | 1080×1920 |
| 4:3 | 1600×1200 |
| 3:4 | 1200×1600 |

每张重新安排人物、标题和留白，不从一张成品机械裁成四张。跨比例保持字体、配色、关键词、文案和两行主标题一致；保证双人都能辨认。

交付前逐张看成品并读取实际像素尺寸；核对文字、人物、边缘、清晰度及主标题占比。精确尺寸调整后再检查比例，不能只拿提示词里的尺寸当结果。保存四张独立文件，便于下载时附一个 ZIP。用户指定文件夹时，将最终交付复制过去并确认文件可读；避免覆盖不相关旧文件。

## 按视频类型写有钩子的 shownote

先从当前内容提炼真实看点，再组织成能直接粘贴发布的正文。前两三行先放最具体的反差、痛点或收益，不从冗长履历、空泛赞美或“本期干货满满”开始。

### 教程类

- 说明工具在什么真实场景解决了什么问题、观众会学到什么。
- 按实际案例组织看点：目标 → 操作方法 → 结果／发现，必要时说明限制。使用用户理解的任务名，不只罗列功能术语。
- 案例数量、是否主动执行、是谁提出目标，都以实际成片为准。例如用户点名指定了某活动，就不能写成 AI 自发发现了该活动。
- 链接、优惠、邀请码、有效期与资料领取方式使用用户已确认内容，不编造收益、折扣或自动化能力。

### 访谈类

- 用本期具体情节起钩：同一场景里的反差、出乎意料的决定、真实踩坑、常见建议与现实结果之间的落差。
- 接一段简短的嘉宾与场景介绍，再列出值得继续看的问题。可以有多个钩子，但各条对应不同看点，不把同一个故事换措辞重复凑数。
- 问题要既有悬念又能在视频找到回应。好笑来自原片细节和主持人真实反应，不靠虚构履历、神化嘉宾或暗示某个车次保证能遇到贵人。
- 如果用户已有栏目发心、招募标准和固定自我介绍，沿用其确认版本，并用适合评论、推荐嘉宾或私信报名的具体 CTA 收尾。不要把人物访谈写成软件教程或未经确认的商业宣传。

正文长短随平台和用户要求调整。通常可包含：强开头、简短背景、数个真实看点、时间轴和相关 CTA；不强制每期固定同样的段落或钩子数量。中文自然、有节奏；事实、语气和受众与本期一致。

## 发布时间轴：从成片回查话题入口

- “时间轴”在此指可复制到简介的章节时间码，不是重新剪辑时间线。先读当前成片时长与映射后的文稿，用实际语句定位每个主要话题入口。
- 主要章节与用户确认的最终结构一致；需要更多钩子时，可以在章节内增加具体问题或故事入口。对外标题可更生动，但不能让人点进去听到另一个话题。
- 用当前帧率换算成片时间，保留内部帧或秒锚点；对外输出顺序递增的 `MM:SS 标题`，长视频需要时用 `HH:MM:SS`。不使用原片时间、旧剪辑稿时间或估算均分时间。
- 开头可用 `00:00` 标出真实开场看点，不默认叫“精彩预告”。名称和起点应能追溯到对应话题；不要每一句都切一章。需要平台可点击章节时核对其当前格式要求。
- 复制到开头的钩子与正文同句是两个位置；给正文故事设入口时，锚定正文那一次播放。新增旁白、钩子、删句、调序后重读受影响时间点，不对所有后续章节盲目统一加秒数。
- 抽查每个时间点附近的文稿或实际成片，确认内容已开始且不是上一话题的结尾；再检查首条、顺序、总时长与最后一章。缺少成片证据时，先提供不带假时间码的章节草案，并明确待校准。
- shownote 的名字、事实和时间轴应保持一致；剪辑更新后按 [时间线同步](timeline-sync.md) 同步已交付的发布素材。

## 发布素材验收

- 封面标题与正式标题相互补充，所需栏目名、教程性质或案例数量完整且有依据。
- 用户认可的字体、配色和换行没有在续改或四比例扩展中漂移；人物身份、真实画面、文字可读性和实际尺寸均已检查。
- shownote 有具体看点与观看理由，全部能在本期内容中找到依据；没有虚构主持人经历、夸大嘉宾成绩或写错任务主体。
- 时间轴来自当前成片，入口与标题对应，改稿后已更新。
- 正文和时间码可直接复制；按需提供 UTF-8 文本／Markdown 与独立封面下载。保存、复制或写好文案不等于已经上传或公开发布。
